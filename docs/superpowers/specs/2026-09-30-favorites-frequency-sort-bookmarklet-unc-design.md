# お気に入り・よく使う順・ブックマークレット登録・UNCパス対応 設計書

## 背景・目的

`/grilling`によるユーザーとの詳細な要件ヒアリングの結果、bookmark-shelf（`bookmarks.html` /
`bookmarks-filesync.html`）の使いやすさについて、以下3つの不満が具体化した。

- **たどり着きづらい**: 検索してもキーワードを思い出せない、タグ・グループの分類自体が多く選ぶのが
  大変、分類内の一覧が長くスクロールして探す、の複合。100件以上のブックマークを想定した際に顕著になる。
- **登録が面倒**: URLを毎回コピーしてこのアプリのタブに貼り付ける手間（このアプリはブラウザ拡張では
  なく単一HTMLファイルのため、閲覧中ページのURLを自動取得する手段が無い）。
- **グルーピングが面倒**: 登録時にグループを選ぶ一手間、および自動化・提案への要望。

加えて、Web以外にWindowsのネットワーク共有（UNCパス）も登録したいという要望があった。

本設計書は、これらに対応する4つの機能追加（お気に入りピン留め・よく使う順自動並び替え・
ブックマークレットによる登録支援・NFS/UNCフォルダパス対応）を扱う。UIレイアウト全般の見直しは
別途frontend-designスキルを使う後続タスクとし、本設計書のスコープには含めない。

## スコープ

### 対象

- `bookmarks.html`・`bookmarks-filesync.html` 両ファイルへの同一パターン適用が基本方針。ただし
  「よく使う順」自動並び替え（R3）のみ、書き込み頻度増加を避けるため`bookmarks.html`限定とする
  （ユーザー確認済み）。
- データモデルへのフィールド追加（`pinned` / `lastAccessed` / `accessCount`）とマイグレーション
- お気に入りピン留め機能（トグルボタン・専用セクション・重複表示）
- 並び替えモード切替（手動順/よく使う順、`bookmarks.html`のみ）とアクセス記録
- ブックマークレットによる登録支援（URLクエリパラメータ経由の自動プリフィル・生成UI）
- NFS/UNCフォルダパスの登録・表示・オープン対応

### スコープ外（ユーザー確認済み）

- 検索対象フィールド（`title`/`url`/`tags`）の拡張はしない
- サイドバーのタグ/グループ絞り込みUIの改善（新規要件としては追加しない）
- グルーピングを楽にする新機能（ドメインベースの自動提案等）は追加しない。既存の一括グループ移動
  （選択モード）を使う運用を継続する
- UIレイアウト全般の見直し（配色・情報密度・レスポンシブ対応）
- モバイル対応（PC専用として設計する）

## 採用アプローチ

### お気に入り・並び替え

既存の手動並び替え（`order`フィールドによるドラッグ&ドロップ）は壊さず温存し、「よく使う順」は
**表示直前の動的ソート**として追加する（データの`order`値は書き換えない）。これにより、モードを
行き来しても手動で組んだ並び順が失われない。

検討した代替案:
- **`order`自体を頻度順で書き換える**: 見送り。モード切替のたびに手動順が破壊され、ユーザーが
  「手動順」に戻した時に元の並びを復元できなくなる。
- **お気に入りをグループ内から除去してセクション間で移動する**: 見送り。グループ内で「このブック
  マークがどこに属しているか」を見失うため、ユーザー要望どおり重複表示（両方に残す）を採用する。

### UNCパス

既存の`file://`パス処理（CLAUDE.md記載: バックスラッシュ等を含む文字列を`URL()`に通さず文字列分割で
扱う）と同じ設計方針を踏襲し、**生のUNCパス文字列をそのまま保持**する（詳細はR5参照）。保存時点で
正規化したURLに変換する案は、UNCの`file://`表現に環境依存の表記ゆれがあるため見送った。

## 機能要件

### R1: データモデル拡張とマイグレーション

`bookmark`オブジェクトに以下を追加する。

- `pinned: boolean`（デフォルト`false`）
- `lastAccessed: number | null`（デフォルト`null`）— 最終アクセスのUNIXタイムスタンプ(ms)。
  `bookmarks.html`のみ更新する
- `accessCount: number`（デフォルト`0`）— アクセス回数。`bookmarks.html`のみ更新する
- `scheme`の許容値に`'unc'`を追加（既存: `'http'` / `'https'` / `'file'`）

マイグレーションは既存の`order`/`groupOrder`と同じ「ロード時に欠損フィールドを一括バックフィル」
方式を踏襲する。`pinned=false`、`lastAccessed=null`、`accessCount=0`で補完する。

`sanitizeBookmark()`（JSON importおよびfilesync版の初回ファイル読込で使う検証ゲート）も本フィールド群
と`scheme==='unc'`を扱えるよう更新する。`pinned`は真偽値に強制、`accessCount`は0以上の整数に強制、
`lastAccessed`は数値または`null`以外は`null`に丸める。

### R2: お気に入りピン留め

- カードに星印等のピン留めトグルボタンを追加する。クリックで`b.pinned`を反転→保存→`render()`。
- `render()`の先頭（通常のグループ横並びセクション群より前）に「未分類」と対称的な「お気に入り」
  特別セクションを追加する。`pinned===true`のブックマークのみを表示する。
- 通常のグループセクション側では、ピン留めされたブックマークも**除外せずそのまま表示**する（同一
  ブックマークにつき2枚のカード要素がDOM上に生成される）。お気に入りセクション側のカードには
  ドラッグイベントを**バインドしない**（グループ内カード側は従来通りドラッグ可能のまま）。
- お気に入りセクションは、既存の検索/タグ/グループによるセクション絞り込みルール（CLAUDE.md記載の
  `renderSections()`挙動）に従う特別セクションとして扱う。すなわち、検索/タグ絞り込みで該当ブック
  マークが0件になれば非表示になり、`state.group`が特定のグループ（または`''`＝未分類）に絞られて
  いる間は非表示になる（他のグループセクション・未分類セクションと同じ扱い）。
- ピン留めされたブックマークが1件も無い場合、お気に入りセクション自体を表示しない。
- `bookmarks-filesync.html`にもピン留め機能自体（トグル・お気に入りセクション・重複表示）は実装する。
  並び替えモード（R3）非対応のため、お気に入りセクション内の並び順は常に手動順（各ブックマークの
  `order`）とする。

### R3: 並び替えモード切替（`bookmarks.html`のみ）

- ツールバー領域に「手動順 / よく使う順」を切り替えるトグルボタンを追加する。
- 状態は`state.sortMode`（`'manual'` | `'frequency'`）。ブラウザリロード後も保持するため、本体データ
  （`bookmarks_data`キー）とは独立した別のlocalStorageキー（例: `bookmarks_sort_mode`）に保存する
  （本体データのスキーマを汚さないため）。
- `'frequency'`モード時、通常のグループセクション・お気に入りセクションいずれも、表示直前に
  以下のスコアで降順ソートして描画する（`order`フィールド自体は書き換えない）。

  ```
  score = accessCount / (daysSinceLastAccess + 1)
  ```

  `lastAccessed === null`（未アクセス）の場合は`daysSinceLastAccess`を十分大きい値として扱い、
  スコアが常に最小になる（未アクセスのブックマークは常に下位）ようにする。
- カードのタイトルリンク（`target="_blank"`）クリック時に、`accessCount`をインクリメントし
  `lastAccessed`を現在時刻で更新し、保存後`render()`を呼ぶ。`target="_blank"`のためクリック
  ハンドラは遷移をブロックせず同期的に実行できる。
- `bookmarks-filesync.html`には本トグルUIおよびアクセス記録処理を追加しない。

### R4: ブックマークレットによる登録支援

- アプリ起動時、`location.search`に`url`パラメータが存在すれば、追加パネルを自動的に開き、
  `url`（および存在すれば`title`）で追加フォームをプリフィルする。
- ヘルプパネル内に「ブックマークレットを生成」導線を追加する。生成されるコードは概ね以下の形で、
  現在の`location.href`（クエリ文字列は除いたベースURL）を埋め込む形で組み立てる。

  ```
  javascript:location.href='<現在のベースURL>?url='+encodeURIComponent(location.href)+'&title='+encodeURIComponent(document.title)
  ```

  実際に開いているファイルのパス（`file:///home/...`等）に依存せず、表示中のページの
  `location.href`から動的に生成するため、ユーザーごとの設置場所の違いを吸収できる。
- 生成したコードはブックマークバーへドラッグ登録できるリンク要素として提示する。
- `bookmarks-filesync.html`は新規タブを開くたびにファイル再接続（ユーザー操作でのアクセス許可）が
  必要という既存の制約をそのまま引き継ぐ（本設計での変更なし、ユーザー確認済み）。
- クエリパラメータ経由で渡された`url`が`classifyUrl()`で許可されないスキームだった場合、通常の
  追加フォームのバリデーションに従う（そのままエラー表示、新規分岐は設けない）。

### R5: NFS/UNCフォルダパス対応

- `classifyUrl()`に、先頭が`\\`で始まる文字列（Windows UNCパス、例: `\\server\share\folder`）を
  検出するルールを追加し、`scheme: 'unc'`として許可する。大文字小文字・末尾スラッシュ等の正規化は
  行わず、入力された文字列をそのまま保持する（既存の`file://`パス処理と同じ方針）。
- 既存の「URL」入力欄にそのまま貼り付けられるようにする（単一欄での自動判定、専用モード切替UIは
  追加しない）。
- `deriveTentativeTitle()`は、UNCパスの場合も既存のfile://パスと同様、末尾のフォルダ/ファイル名を
  タイトル候補として返す。
- カードのクリック時（またはボタン操作）は、都度`\`→`/`変換と`file:`プレフィックス付与を行い
  `file://server/share/folder`相当のリンクとして開くことを試みる（保存値自体は変換しない）。
- ブラウザ・OS環境によっては開けない場合があるため、開くボタンの隣に「パスをコピー」ボタンを
  併置する。既存のローカル`file://`パス（`scheme==='file'`）にも同ボタンを追加し、UNCと同じ
  UIパターンで統一する（実装コストが低く一貫したUXになるため、本設計で決定する）。
- 検索対象フィールド（`title`/`url`/`tags`）は変更しないため、UNCパスは`url`フィールド経由で検索に
  引っかかる（既存のfile://パスと同待遇）。

## エッジケース

- **お気に入りが1件も無い場合**: お気に入りセクション自体を表示しない（R2）。
- **お気に入り対象のブックマークが削除された場合**: データごと消えるため、お気に入りセクションからも
  自動的に消える。特別な後処理は不要。
- **お気に入り対象のブックマークが属するグループが削除された場合**: 既存のグループ削除処理に従い
  「未分類」扱いになる。お気に入りセクションには引き続き表示される。
- **検索/タグ/グループ絞り込みとお気に入りセクションの組み合わせ**: お気に入りセクションも他の
  セクションと同じ絞り込みルールに従う（R2に既述）。
- **`lastAccessed`が`null`のブックマークが「よく使う順」モードでソートされる場合**: 常に最下位
  （スコア最小）として扱う（R3に既述）。
- **ブックマークレット経由のクエリパラメータに許可外スキームのURLが渡された場合**: 通常の追加
  フォームのバリデーションでエラー表示（R4に既述）。
- **UNCパスの「開く」操作が失敗する場合**: ブラウザは失敗を検知できず静かに無視することが多いため、
  エラーハンドリングは行わず、常に隣にある「パスをコピー」ボタンで代替する（R5に既述）。
- **filesync版でのお気に入り**: ピン留め機能自体は実装するが、並び替えモードは常に手動順のまま
  （R2/R3に既述）。

## 対象ファイルと変更範囲

- `bookmarks.html` — R1〜R5すべてを実装（並び替えモードはこのファイルのみの機能）
- `bookmarks-filesync.html` — R1・R2・R4・R5を実装（R3の並び替えモードUIとアクセス記録処理は対象外）

## テスト方針

自動テストランナーが存在しないリポジトリのため、`browser-manual-e2e`プロファイル
（claude-in-chromeによる操作→DOM状態・見た目の確認）に従って検証する。最低限、以下を1シナリオずつ
確認する。

- ピン留めトグル→お気に入りセクションに表示され、かつ元のグループ内表示にも残ること（R2）
- お気に入りセクション内でドラッグしても並び替えが起きないこと、グループ内では従来通りドラッグ
  できること（R2）
- 検索/タグ/グループ絞り込み時のお気に入りセクションの表示・非表示切り替え（R2）
- 「手動順」⇔「よく使う順」トグルで表示順が切り替わり、`order`フィールド自体は変化しないこと（R3、
  `bookmarks.html`のみ）
- ブックマークを開くと`accessCount`/`lastAccessed`が更新されること（R3、`bookmarks.html`のみ）
- `bookmarks-filesync.html`に並び替えモードUIが表示されないこと（R3）
- `?url=...&title=...`パラメータ付きで起動すると追加フォームが自動プリフィルされること（R4）
- ブックマークレット生成UIから取得したコードが、想定通りのクエリパラメータ付きURLへ遷移すること（R4）
- UNCパス（`\\server\share\folder`）を登録できること、カード表示・「開く」操作・「パスをコピー」
  操作が機能すること（R5）
- 既存のローカル`file://`パスにも「パスをコピー」ボタンが追加されていること（R5）
- JSONエクスポート/インポートで新規フィールド（`pinned`/`lastAccessed`/`accessCount`/`unc`スキーム）が
  正しく往復すること（R1）
