# タグ/グループの使い分け明確化とレイアウト固定 設計書

## 背景・目的

bookmark-shelf（`bookmarks.html` / `bookmarks-filesync.html`）では、タグとグループが以下の点で
使い分けが曖昧になっている。

- サイドバーの `#tag-nav` / `#group-nav` は、選択中ボタンの見た目（`.sidebar li button.active`、
  `--amber`背景）が完全共通で、どちらのフィルタを選んでいるか一見して区別できない。
- カード一覧を見ても、現在有効なフィルタが「タグ」なのか「グループ」なのかを常時示す表示がどこにも無い。
- 入力面では、タグ（複数・自由入力）とグループ（単一・自由入力＋datalist補完）で入力方式が非対称な上、
  どちらも自由入力のため、意味の使い分け（グループ＝置き場所、タグ＝横断ラベル）が入力時に伝わらず、
  運用上どちらに何を入れるか迷いが生じている。

これに加えて、次の2点も同じ作業機会にまとめて対応する。

- ページ全体が単一のdocumentスクロールになっており、下にスクロールするとヘッダー（検索・操作ボタン）と
  サイドバー（タグ/グループnav）が画面外に流れて操作しづらい。
- カードに表示されているURL文字列（`.card-url`）は、タイトルリンクのhrefと重複しており不要。

## スコープ

### 対象

- `bookmarks.html`・`bookmarks-filesync.html` 両ファイルへの同一パターン適用（UIロジックは重複しており、
  CLAUDE.mdの方針どおり両方に手を入れる）
- サイドバーnavの色分け、常時表示フィルタインジケーター、フォームの説明文追加
- タグ/グループのチップ選択UI（新規追加フォーム・カードのインライン編集フォーム・一括グループ化バーの
  3箇所で共通化）
- ヘッダー/サイドバーのスクロール固定（デスクトップ幅のみ）
- カードのURL表示（`.card-url`）の削除

### スコープ外（ユーザー確認済み）

- データモデル（`tags[]` / `group` / `groupOrder`）自体の変更・グループの廃止統合は行わない
- タグの一括管理モーダル（グループには既に `#group-manage-overlay` があるが、タグには同種のUIを
  新設しない）
- モバイル幅（760px以下）でのヘッダー/サイドバー固定

## 採用アプローチ

タグ・グループそれぞれ既存のカード上の意匠（タグ＝ワイン色スタンプ、グループ＝セージ色枠のセクション）
をそのまま「その種別を示す色」としてサイドバーnav・フィルタインジケーターにも展開し、新しい色や絵文字を
持ち込まない。既存デザイン言語（ワイン/セージ/アンバーの3色運用）を壊さず一貫性を保つのが狙い。

検討した代替案:
- **アイコン（絵文字）で種別を区別**: タグ/グループの区別は即座に付くが、このアプリは現状絵文字を
  一切使っておらず、スタンプ風の紙質感デザインと調和しないため見送った。
- **タグ入力を完全な選択式（新規タグも既存候補からのみ）にする**: 誤入力防止には強いが、初回はタグが
  0件のため新規作成の手段を別途用意せざるを得ず、結局自由入力欄が必要になる。素直に「既存はチップ選択、
  新規は自由入力」の併用とした。

## 機能要件

### R1: サイドバーnavの色分け

`#tag-nav` の選択中ボタン（`.active`）はワイン色反転（`.tag-stamp.active` と同系統）、`#group-nav` の
選択中ボタンはセージ色反転にする。非選択時の見た目は現状維持。

### R2: 常時表示フィルタインジケーター

検索・並び替えバー付近（`.app-header` 直下、既存の `#result-count` 表示に近い位置）に、`state.tag` /
`state.group` のいずれかが有効な間だけ表示されるインジケーターチップを追加する。

- タグフィルタ中: 「タグ: `{state.tag}` ×」をワイン色で表示
- グループフィルタ中: 「グループ: `{state.group === '' ? '未分類' : state.group}` ×」をセージ色で表示
- 両方同時に有効な場合は両方のチップを並べて表示する
- ×クリックで該当する `state.tag` / `state.group` のみを `null` に戻し `render()` を呼ぶ（もう一方の
  フィルタは維持）

### R3: 入力フォームの説明文

タグ入力欄・グループ入力欄それぞれの近傍（ラベルの下、または `.hint` と同様の位置）に短い説明文を
常時表示する。

- グループ欄: 「グループ＝1つだけ選べる置き場所」
- タグ欄: 「タグ＝複数付けられる横断ラベル」

新規追加フォーム・カードのインライン編集フォーム両方に表示する（一括グループ化バーは選択操作のみの
簡易UIのため対象外）。

### R4: タグ/グループのチップ選択UI

新規追加フォーム（`#add-form`）、カードのインライン編集フォーム（`renderEditCard`）、一括「グループに
まとめる」バー（`#selection-bar`）の3箇所で、共通のレンダリング処理を使う。

**タグ**
- 既存タグ一覧（`getAllTags()`相当、全ブックマークの`tags[]`の重合集合）をチップとして表示し、クリックで
  選択トグル（複数選択可、選択中は強調色）
- 新規タグ用の自由入力欄を併設し、従来どおりカンマ区切りで複数の新規タグを一度に入力できる
  （`parseTags()`のパースロジックは流用）
- 送信時は「選択済みチップ」＋「新規入力欄からパースした値」を結合し重複除去したものを `tags[]` とする

**グループ**
- 既存グループ一覧（`getGroups()`相当）をチップとして表示し、クリックで単一選択（選び直し可、選択中は
  強調色）
- 新規グループ用の自由入力欄を併設（単一値、カンマ区切りパースは無し）
- 新規グループ欄に文字が入力された場合、既存チップの選択状態は自動解除する（逆に既存チップをクリック
  すると新規グループ欄はクリアする）。これはグループが単一値であることを入力UI上でも一貫させるための
  仕様であり、送信時は「新規グループ欄に値があればそれを優先、無ければ選択中チップの値を使う」
- `datalist`（`#group-list`）によるオートコンプリートは本UIに置き換わるため削除する

いずれも既存の `getGroupOrderForName()` 経由の `groupOrder` 付与ロジックはそのまま使う（グループの
決定方法が変わるだけで、決定後の後続処理は変更しない）。

### R5: ヘッダー/サイドバーのスクロール固定（デスクトップ幅のみ）

- `.app-header` を `position: sticky; top: 0;` にし、`z-index` をヘルプパネルより高く設定する
- `.sidebar` は760px超の画面幅で `position: sticky; top: <ヘッダー高さ>;` とし、
  `max-height: calc(100vh - <ヘッダー高さ>); overflow-y: auto;` を付与する。タグ/グループ一覧が
  増えてもサイドバー内部だけが独自スクロールし、ページ全体のスクロールには追従しない
- `.help-panel` は既存の `position: sticky; top: 0;` のままだとヘッダーの後ろに隠れるため、`top` を
  ヘッダー高さ分に変更し、ヘッダー直下に張り付くよう調整する（ヘッダー固定に伴う必須の追従修正）
- ヘッダー高さの基準値は、既存の `.layout { min-height: calc(100vh - 64px); }`（bookmarks.html:305）が
  前提としている64pxをそのまま流用し、新規の値を持ち込まない
- 760px以下（`.layout`が`flex-direction: column`に切り替わる幅）ではこのRの対象外とし、現状の
  一体スクロールのまま変更しない

### R6: カードのURL表示を削除

`renderCard()` 内の `<p class="card-url">{url}</p>`（`card-title-wrap`内、タイトル直下）を削除する。
href・クリックで開く動作（`.card-title a`）・favicon表示（`b.domain`経由）はこの要素と依存関係が
無いため影響しない。対応する未使用CSS（`.card-url`）も削除する。

## エッジケース

- タグ・グループが1件も存在しない状態（初回利用時）→ チップ一覧は空表示にし、新規入力欄のみが機能する
- フィルタインジケーター（R2）表示中に、選択していたタグ/グループ自体が削除されて消滅した場合 →
  既存の`render()`のクリーンアップ処理（`state.tag`/`state.group`を`null`に戻す）によりインジケーターも
  自動的に消える。新たな分岐は不要
- 一括グループ化バー（`#selection-bar`）でのグループチップ選択 → R4のグループ側チップ選択と同じ
  コンポーネントを使うが、対象は選択中の複数ブックマーク全件への一括適用である点は現状の
  `#group-assign-btn` の挙動を変更しない
- ウィンドウを760px境界をまたいでリサイズした場合 → CSSの`@media`切り替えのみで対応し、JSでの
  sticky有効/無効の出し分けは行わない

## 対象ファイルと変更範囲

- `bookmarks.html` — データ層（`loadData`/`saveData`）以外の上記ロジック・CSSを追加/変更
- `bookmarks-filesync.html` — 同一パターンを適用（行番号オフセットのみで構造は共通）

## テスト方針

自動テストランナーが存在しないリポジトリのため、`tdd-gates`の`browser-manual-e2e`プロファイル
（claude-in-chromeによる操作→DOM状態・見た目の確認）に従って検証する。最低限、以下を1シナリオずつ
確認する。

- タグ/グループnavの色分け表示（R1）
- タグ・グループそれぞれのフィルタ適用時のインジケーター表示と×での解除（R2）
- 新規追加・編集・一括グループ化それぞれでのチップ選択によるタグ/グループ付与（R4）
- スクロール時のヘッダー/サイドバー固定とサイドバー内部スクロール、ヘルプパネルとの重なり無し（R5）
- デスクトップ幅→モバイル幅リサイズ時の固定解除（R5）
- カード上にURL文字列が表示されないこと、リンク・favicon表示は従来通りであること（R6）
