# キーボードのみでの操作対応 設計書

## 背景・目的

bookmark-shelf（`bookmarks.html` / `bookmarks-filesync.html`）は現状、キーボード操作の実装が皆無である
（`tabindex`/`keydown`/`accesskey`/Escによるモーダル閉じ、いずれも0件、grep確認済み）。ボタンやリンクは
ネイティブ要素のためTab到達＋Enter/Spaceでの発火自体は可能だが、ショートカットキーやカード間の方向キー
移動が無く、マウス無しでの実運用には力不足である。

唯一の既存の「マウス不要な代替手段」は、グループセクション並べ替えの▲/▼ボタン（`moveGroupStep`、
bookmarks.html:1454-1461）。この設計思想（ドラッグ操作にボタンでの代替を用意する）を手本に、今回は以下
2点を優先して対応する。

1. ショートカットキー体系（グローバル + カード一覧内）
2. 全体のTab移動とフォーカス基盤（roving tabindex、Escでのパネル閉じ）

## スコープ

### 対象

- `bookmarks.html`・`bookmarks-filesync.html` 両ファイルへの同一パターン適用（UIロジックは重複しており、
  CLAUDE.mdの方針どおり両方に手を入れる）
- グローバルショートカットキー（`/` `n` `s` `?` `Escape`）
- カード一覧の roving tabindex とカード内ショートカット（`↑`/`↓` `Enter` `e` `Delete`/`Backspace` `Space`）

### スコープ外（ユーザー確認済み）

- ドラッグ&ドロップの代替（カード並べ替え `moveBookmark`、グループ末尾移動 `moveToGroupEnd`）— 別タスク
- タグナビ・グループナビ内での矢印キー移動 — 既存のTab順（button要素）で十分と判断
- 真のフォーカストラップ — インラインパネルであり厳密なモーダルではないため過剰と判断

## 採用アプローチ

既存の「`document.addEventListener('click', ...)` + `data-action`属性 + `closest()`」というイベント委譲
パターン（bookmarks.html:902-909）を踏襲し、対になる `keydown` 委譲リスナーを1本追加する。加えてカード
一覧に roving tabindex を導入する。ARIAリストボックス/グリッドパターンへの完全準拠（フォーカス状態を
`state`で正式管理する等）は、`render()`が毎回DOM全体を再生成する現設計と相性が悪くオーバースペックな
ため見送り、一時的なモジュールスコープ変数でのフォーカス保持に留める軽量な方式を採る。

検討した代替案:
- **ARIAリストボックス/グリッドパターンへの完全準拠**: アクセシビリティ標準に最も忠実だが、`render()`が
  状態から全部作り直す設計と相性が悪くフォーカス位置の保持・復元ロジックが新たに必要になり、実装コスト
  が最も高い。今回のスコープに対してオーバースペックと判断し見送った。
- **最小実装（検索フォーカスとEscのみ）**: 実装コストは最小だが、ユーザーが優先度で選んだ「ショートカット
  キー体系」「全体のTab移動基盤」の狙いに対して物足りないため見送った。

## 機能要件

### R1: グローバルショートカットキー

新規の `document.addEventListener('keydown', ...)` を追加する。テキスト入力欄（検索ボックス・各種フォーム
のinput/textarea）にフォーカスがある間は、**`Escape`を除いて**無効化し、通常のタイピングを妨げない。
`Escape`は入力欄・フォーム内にフォーカスがあっても常に有効とする（編集フォーム自体がinput/textareaで
構成されており、フォーム内で`Escape`が効かないと閉じられなくなるため。抜け漏れ候補への回答=ユーザー確認済み）。

| キー | 動作 |
|---|---|
| `/` | 検索ボックス（`#search-input`）へフォーカス |
| `n` | 新規追加パネルの開閉（既存 `#toggle-add-btn` のクリックと同等の処理を呼ぶ。`#toggle-add-btn`が`disabled`の場合は何もしない。詳細はR4） |
| `s` | 選択モードのトグル（既存 `#toggle-select-btn` と同等。`disabled`の場合は何もしない。詳細はR4） |
| `?` | ショートカット一覧ヘルプの表示/非表示（新規UI、既存の隠しsectionパターンに倣う） |
| `Escape` | 入力欄フォーカス中でも常に有効。手前から順に閉じる：ヘルプ → 編集/追加/グループ名リネームのフォーム → 選択モード解除 |

### R2: カード一覧の roving tabindex + ショートカット

各 `.bookmark-card` のルート要素に `tabindex` を付与し、フォーカス中の1枚だけ `tabindex="0"`、他は
`tabindex="-1"`。表示中の全カードをDOM順で1本のリストとして扱う（セクションをまたいでの移動も含む）。

カード内の既存フォーカス可能要素（タイトルリンク・タグボタン・編集/削除ボタン・ID/パスワードコピー・
パスワード表示切替・選択チェックボックス。`renderCard`, bookmarks.html:1463-1524）は、roving tabindexの
対象外として`tabindex="-1"`にし、Tabキーでは到達させない（抜け漏れ候補への回答=ユーザー確認済み）。
タイトルリンクを含めるのは、含めないと「カードルートでのTab押下は一覧を抜ける」という直後の規定が
成立しない（リンクにフォーカスが入ってしまう）ため。URLを開く手段は下表の`Enter`のみとする。これらの
操作は下表のショートカットキー経由でのみ行う。カードルートにフォーカスがある状態でのTab押下は一覧を抜けて
次のTabストップ（次のUI要素）へ進む。

| キー | 動作 |
|---|---|
| `↑` / `↓` | 前後のカードへフォーカス移動 |
| `Enter` | カードのURLを開く |
| `e` | そのカードの編集フォームを開く |
| `Delete` / `Backspace` | そのカードを削除（確認は既存の `confirm()` のまま）。削除後は次のカードへフォーカス移動、次が無ければ前のカードへ、それも無ければ（一覧が空になった場合）どこにもフォーカスしない（抜け漏れ候補への回答=ユーザー確認済み） |
| `Space` | 選択モード中はチェックボックスをトグル |
| `t` | フォーカス中カードのタグで絞り込みを巡回（複数タグがあれば押すたびに次のタグへ、最後のタグの次で絞り込み解除。タグが無ければ何もしない） |
| `c` | フォーカス中カードのログインIDをコピー（`loginId`が無ければ何もしない） |
| `p` | フォーカス中カードのパスワードをコピー（`loginPassword`が無ければ何もしない） |

**CP-B指摘への回答（ユーザー確認済み）**: roving tabindex導入によりタグボタン・ID/パスワードコピー・
パスワード表示切替ボタンがTabで到達不能になる件について、`t`/`c`/`p`の代替ショートカットを追加する
ことで解消する。ただし**パスワード表示/非表示切替（`toggle-reveal`）には代替ショートカットを設けない**
（キーボード操作では画面に表示せずコピーのみで用が足りるとユーザーが判断したため、意図的にマウス専用の
まま残す）。

### R3: フォーカス保持と初期値

`render()`が呼ばれるたびにDOM全体が再生成される（renderSections内、bookmarks.html:1169-1251相当。
カード自体のドラッグイベントのbind呼び出しは1249行）ため、フォーカス中カードの`id`をモジュールスコープの一時変数
（stateには含めない）で保持し、再描画後に該当カードへ`tabindex="0"`と`focus()`を再適用する。

まだ一度もカードがフォーカスされていない初期状態（ページロード直後、モジュールスコープ変数が未設定）では、
表示中カードの先頭（DOM順で最初のカード）を`tabindex="0"`の初期値とする（抜け漏れ候補への回答=ユーザー
確認済み）。表示中カードが0件の場合は、どのカードにも`tabindex="0"`を設定しない。

### R4: filesync固有 — ファイル未接続時のショートカット無効化

`bookmarks-filesync.html`では、ファイル未接続時に`#toggle-add-btn`/`#toggle-select-btn`が`disabled`
属性つきで初期描画され、`boot()`（同ファイル1036行〜）がファイル接続/再接続に成功して初めて
`HEADER_BUTTON_IDS`（同995行）経由で有効化される（bookmarks-filesync.html:751-752）。`n`/`s`
ショートカットキーは、対応するボタンが`disabled`である間は何もしない（既存のクリックでの保護と同じ
挙動に揃える。抜け漏れ候補への回答=ユーザー確認済み）。`bookmarks.html`（localStorage版）にはこの
disabled状態が存在しないため、本要件はfilesync版のみに適用する。

## エッジケース

- フォーカス中カードが検索・フィルタで表示から消えた場合 → 一覧先頭カードへフォーカスを移す。
- 編集フォーム表示中（`renderEditCard`でカードがフォームに差し替わる間）→ そのカードをroving tabindex
  対象から外し、フォーム内inputへ自然にTab遷移させる。
- `Escape`押下時に複数の「開いているもの」が同時に存在する場合 → 手前から順（ヘルプ→フォーム→選択モード）
  に1段階ずつ閉じる。
- 表示中カードが0件（検索結果無し等）の場合 → 矢印キー操作は何もしない。

## 対象ファイルと変更範囲

- `bookmarks.html` — データ層（`loadData`/`saveData`）以外の上記ロジックを追加（R4は対象外）
- `bookmarks-filesync.html` — 同一パターンを適用（行番号は約301行分オフセットするのみで構造は共通。R4を
  追加で適用）

## CP-A抜け漏れ候補への回答（ユーザー確認済み）

1. Escapeキーと入力欄ガードの矛盾 → Escapeのみ常に有効（R1に反映）
2. roving tabindexとカード内フォーカス可能要素の共存 → 子要素は`tabindex="-1"`にして封じ、操作は
   ショートカットキー経由のみ（R2に反映）
3. 削除後のフォーカス移動先 → 次のカード（無ければ前のカード、それも無ければどこにもフォーカスしない）
   （R2に反映）
4. ロービングtabindexの初期値 → 表示中カードの先頭（R3に反映）
5. filesync固有: ファイル未接続時のn/sショートカット → 対応ボタンが`disabled`の間は無効化（R4として新設）

## テスト方針（詳細はCP-Bで受入基準・シナリオへ展開）

自動テストランナーが存在しないリポジトリのため、`tdd-gates`の`browser-manual-e2e`プロファイル
